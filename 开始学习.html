setupUi与ui指针

Widget::Widget(QWidget *parent)
    : QWidget(parent)
    , ui(new Ui::Widget)
{
    ui->setupUi(this);
}

Widget::~Widget()
{
    delete ui;
}

Ui::Widget 是生成的辅助类，不是窗口本身。setupUi(this) 执行后才建立控件和布局，因此访问 ui->控件 要放在它之后。delete ui 释放辅助对象；控件对象主要由 QObject 父子关系管理。

控件的 objectName 决定生成的成员名，text 只是显示文字。修改 .ui 后应保存并重新构建，不要直接修改 ui_widget.h 或 ui_mainwindow.h。统一模板与 Designer 操作 提供完整说明。

本章要解决的问题

Designer 将界面保存在 .ui XML 文件中，构建时 uic 生成 ui_mainwindow.h。mainwindow.h 用前向声明保存 Ui::MainWindow *ui；mainwindow.cpp 包含生成的头文件，在构造函数中创建辅助对象、调用 ui->setupUi(this)，在析构函数中 delete ui。

参数与行为边界

Qt Creator 向导常用 Ui::MainWindow *ui；new 出来的包装器需要 delete ui。这个 delete 释放包装器，不是要求你手动逐个 delete 其所有子控件。ui_*.h 每次构建可能重新生成，不应手动修补它来解决错误。

遇到问题时先区分三个层次：编译错误检查声明、头文件与构建配置；界面无反应检查连接、接收对象与生存期；运行结果不对检查输入、返回值和分支是否真正执行。可以先在连接入口记录一条日志，再在结果处理处记录一条，定位中间哪一步没有到达。

// 安全示例 先构造父对象 再构造子对象

信号和槽的基本连接

把事件和处理代码连起来

auto *button = new QPushButton("关闭窗口", this);
connect(button, &QPushButton::clicked,
        this, &QWidget::close);

这行代码可以读成：button 发出 clicked 时，调用当前窗口的 close。connect 建立连接时不会立刻关闭窗口；真正触发 clicked 后才调用处理函数。&QPushButton::clicked 是成员函数指针，写连接时不加 ()，否则就变成调用函数。
### 四个位置怎样记

connect(发送对象, &发送类::信号,
        接收对象, &接收类::处理函数);

前两个参数回答“谁发出什么通知”，后两个参数回答“由哪个对象执行哪个函数”。在 Widget 成员函数中可以直接写 connect；在普通函数如 main 中通常写 QObject::connect。
clicked 的签名含 bool checked 参数，而 close() 不接收参数。这仍可连接，因为处理函数可以忽略信号末尾的参数。函数指针连接要求对应参数兼容，可存在允许的隐式类型转换；不能把不兼容的参数强行连起来。参考6
### 槽函数并不都必须返回 void
自定义信号通常声明为 void；槽是普通 C++ 函数，可以有返回值。但普通信号通知不用于收集槽的返回值。例如 QWidget::close() 返回 bool，也能作为这里的处理函数。入门自定义槽写成 void 最直观。
新式 connect 可以连接普通成员函数，也可以连接 Lambda 等可调用对象。若要声明传统元对象槽，可放在 public slots: 或 private slots: 下；不是所有被连接的成员函数都必须写在 slots 区域。参考7
### 一次信号与多个处理函数
可以一对多、多对一，也可以信号连接信号。同线程直接连接时，同一信号连接的多个处理函数按建立连接的顺序调用。跨线程或队列连接涉及事件投递，不应据此推断不同线程中处理完成的先后顺序。参考6参考7

重载信号与断开连接

为什么重载必须指定版本

// 在拥有 teacher 和 student 的作用域中
connect(teacher,
        qOverload<const QString &>(&Teacher::hungry),
        student,
        qOverload<const QString &>(&Student::treat));

qOverload<>() 选择无参版本；qOverload<const QString &>() 选择参数为 const QString & 的版本。这里模板参数必须与函数真实声明相符，不能把 QString 与 const QString & 当成同一个成员函数类型。
原笔记使用成员函数指针变量的思路也成立：

void (Teacher::*sig)(const QString &) = &Teacher::hungry;
void (Student::*slot)(const QString &) = &Student::treat;
connect(teacher, sig, student, slot);

左边从中间读：sig 是 Teacher 类的成员函数指针，该函数接收 const QString &，返回 void。qOverload 只是让选择版本的表达更紧凑，两个示例是替代写法，不要重复连接。
### 保存连接句柄再断开

QMetaObject::Connection c = connect(
    teacher, qOverload<>(&Teacher::hungry),
    student, qOverload<>(&Student::treat));

QObject::disconnect(c);

disconnect 是函数，不是 C++ 关键字。保存返回的句柄，能准确断开这一条连接，尤其适合 Lambda。句柄变量离开作用域本身不会自动断开连接。参考6
发送者或接收者销毁时，相关连接会被自动清理。Lambda 使用带 context 的 connect 时，context 销毁也会使该连接断开；但 Lambda 捕获的其他对象是否仍然存活，仍要自己保证。
### 重复输出不一定是信号发了两次
同一条连接代码执行两次，默认会建立两条连接，信号发出一次也可能让处理函数运行两次。优先检查初始化函数是否重复调用，避免在反复进入的函数中不断 connect。Qt::UniqueConnection 有适用限制，不能当成所有 Lambda 连接的通用去重开关。参考6

Lambda的基本结构与调用

它解决什么问题

int add(int a, int b)
{
    return a + b;
}
int result = add(3, 4);  // result 为 7

改写成 Lambda 后：

auto add = [](int a, int b) -> int {
    return a + b;
};
int result = add(3, 4);  // 仍然为 7

auto 让编译器推导 add 的类型。Lambda 产生的是一个可调用的函数对象，可用 add(...) 调用；它不只是“没有名字的普通函数”。结尾的分号结束变量定义，不能漏掉。
### 一段语法分成五部分

[捕获列表](参数列表) mutable -> 返回值类型 {
    函数体
}

捕获列表回答“如何使用外部局部变量”；参数列表回答“调用时需要传什么”；mutable 决定是否允许修改值捕获的副本；返回类型回答“返回什么”；函数体写实际执行的语句。参考8
最开始只用最简单的 []() { ... }。不要把 mutable 和返回类型当成每次必填的内容。返回类型通常可以由 return 推导，上面的 -> int 可以省略。
### 定义和执行是两件事

auto say = []() { qDebug() << "你好"; };
// 到这里还没有输出
say();  // 此时才执行函数体并输出

写出 Lambda 只是创建可调用对象。调用 say() 才运行它的函数体。connect 中也是先登记这段行为，等信号触发后再执行。

捕获列表和参数列表

先看变量是从哪里来的

int base = 10;
auto addBase = [base](int x) {
    return base + x;
};
qDebug() << addBase(3);  // 13
qDebug() << addBase(8);  // 18

base 在 Lambda 外部定义，创建 Lambda 时通过 [base] 保存一个副本。x 是每次调用时传入的参数，addBase(3) 中 x 是 3，addBase(8) 中 x 是 8。二者都能在函数体里使用，但来源和进入函数体的时间不同。
| 观察点 | 捕获列表 [base] | 参数列表 (int x) |
| --- | --- | --- |
| 数据来源 | 外部作用域中已有的局部变量 | 调用者本次提供的实参 |
| 进入时机 | 创建 Lambda 时建立捕获 | 每次调用时初始化参数 |
| 外面怎样写 | [base] 或 [&base] 等 | addBase(3) 中的 3 |
| 主要用途 | 保留这段行为所需的上下文 | 处理每次调用不同的输入 |
### 没捕获就不能随便用外面的局部变量

int base = 10;
// 错误示意 base 是外部自动存储期局部变量
// auto f = [](int x) { return base + x; };

auto f = [base](int x) { return base + x; }; // 正确

[] 表示没有捕获，不等于函数体什么都不能做。它仍能使用自己的参数、函数体内新建的局部变量，以及无需捕获就可访问的全局变量或静态变量等。
### Qt 中两种来源同时出现

QString tag = "保存按钮";
connect(button, &QPushButton::clicked, this,
        [tag](bool checked) {
    qDebug() << tag << checked;
});

tag 来自创建连接时所在的作用域；checked 来自按钮每次发出的信号。不要把 checked 也写进捕获列表来替代参数，那会改变它的数据来源。普通按钮默认不可勾选，若要观察 checked 切换，可先 button->setCheckable(true)。

值捕获与指针捕获

外面的值改变 副本不会跟着改变

int n = 10;
auto read = [n]() { return n; };
n = 20;
qDebug() << read();  // 10
qDebug() << n;       // 20

执行到 [n] 时，Lambda 保存了当时 n 的值 10。之后 n = 20 修改的是外面的变量。调用 read() 读取的是自己的副本，因此结果仍然是 10。
可以把值捕获理解为“拍下当时的值”，但这只是帮助理解的比喻：实际复制什么、复制后共享什么，由被捕获类型自己的复制语义决定。对 int 而言就是保存一个独立数值。
### 默认不能给值捕获的普通变量赋值

int n = 10;
auto read = [n]() {
    // n = 30;  // 编译失败 当前不能修改这个副本
    return n;
};

这是 Lambda 默认调用运算符的 const 限制。之后可以用 mutable 允许修改副本，但 mutable 不会把值捕获变成引用捕获。参考8
### 捕获指针复制的是地址

int number = 10;
int *ptr = &number;
auto change = [ptr]() { *ptr = 30; };
change();
qDebug() << number;  // 30

副本 ptr 和外面的 ptr 都指向同一个 number。虽然复制了指针，但没有复制它指向的 int。*ptr = 30 改变目标对象，所以外部 number 也变了。这也解释了为什么捕获 this 后可以修改窗口成员。
值捕获不自动延长指针目标的生命。如果捕获的是某个 QWidget*，后面控件先被删除，再使用这个地址仍然危险。学习时要分别问两件事：“复制了什么”和“目标对象还活着吗”。
### 什么时候适合值捕获
希望保存创建连接时的一段文字、一个编号或一个固定配置时，可以显式值捕获。例如 [tag] 比默认 [=] 更容易看清这段代码依赖了什么。需要读取不断变化的状态时，应考虑引用或对象成员，而不是误以为旧副本会自动更新。

引用捕获与生命周期

修改会反映到外部

int n = 10;
auto increase = [&n]() { ++n; };
increase();
qDebug() << n;  // 11
n = 40;
increase();
qDebug() << n;  // 41

[&n] 让函数体通过引用访问外面的 n，因而既能看到外部后续变化，也能修改外部值。这种修改不需要 mutable，因为修改的不是值捕获副本。
### 看懂常见捕获写法
| 写法 | 含义 |
| --- | --- |
| [] | 不捕获外部局部变量 |
| [n] | 按值捕获 n |
| [&n] | 按引用捕获 n |
| [n &m] 的正确写法为 [n, &m] | n 用副本 m 用引用 |
| [=] | 对需要捕获的外部局部变量默认按值捕获 |
| [&] | 对需要捕获的外部局部变量默认按引用捕获 |
| [this] | 保存当前对象的 this 指针 可访问对象成员 |
混合捕获时，逗号分隔每一项。入门优先把所需变量显式写出来，例如 [count, &total]，便于发现外部依赖。默认捕获不等于无条件捕获所在作用域的一切。参考8
### 最大的风险是变量已经不存在

// 错误示意 不要这样给按钮长期保存回调
void Widget::setupButton()
{
    int count = 0;
    auto *button = new QPushButton("计数", this);
    connect(button, &QPushButton::clicked, this,
            [&count]() { ++count; });
}

setupButton() 返回后，局部 count 已结束生命周期。按钮以后被点击时才执行 Lambda，这时引用已经悬空，访问它属于未定义行为。即使 connect 写了 this 作为上下文，也不能保护这个局部 count。

mutable与副本状态

拆解原来的例子

int m = 10;
auto fun = [m](int a, int b) mutable {
    qDebug() << "lambda is running!";
    m = 300;
    return a + b;
};
int sum = fun(100, 200);
qDebug() << sum;
qDebug() << m;

依次输出的内容是 lambda is running!、300、10。第一行来自函数体的日志；第二行的 300 是 a + b 的返回值；第三行的 10 来自外部 m。注意这里“内部 m 被赋为 300”和“返回值也是 300”只是数值恰好相同，没有因果关系。
执行过程：① 外部 m 初始化为 10。② [m] 复制 10 进入函数对象。③ mutable 允许给内部副本重新赋值。④ 调用时 a 为 100，b 为 200。⑤ m = 300 改变内部副本。⑥ return a + b 返回 300。⑦ 外部 m 始终没有改变。
### 改写一下 就能看出副本会保留

int m = 10;
auto next = [m]() mutable { return ++m; };
qDebug() << next();  // 11
qDebug() << next();  // 12
qDebug() << m;       // 10

对同一个 next 对象连续调用，使用的是同一个内部副本，所以从 10 增到 11，再增到 12，并不是每次调用都重新从外部复制 10。创建 Lambda 和调用 Lambda 要分开理解。
### 如果想改变外面的 m

int m = 10;
auto next = [&m]() { return ++m; };
qDebug() << next();  // 11
qDebug() << m;       // 11

这里使用引用捕获，不需要 mutable。记忆时分开两条：值或引用决定“访问的是副本还是外部变量”；mutable 决定“能否修改值捕获副本”。它们解决的是不同问题。
本笔记采用 C++17，带 mutable 的 Lambda 保留空参数列表 ()，写作 [m]() mutable { ... }。这样也能避免混淆不同 C++ 标准下的省略规则。

this与窗口成员

this 本来就是一个指针

// widget.h 中 Widget 类的 private 区域
int count_ = 0;

// Widget 构造函数中
auto *button = new QPushButton("点击计数", this);
connect(button, &QPushButton::clicked, this, [this]() {
    ++count_;
    setWindowTitle(QString("已点击 %1 次").arg(count_));
});

count_ 等价于 this->count_，setWindowTitle(...) 等价于 this->setWindowTitle(...)。通过保存的 this 指针访问当前窗口，所以不需要把每个成员都单独放进捕获列表。
### 为什么不用 mutable 也能修改成员
[this] 保存的是 this 指针，修改的是它指向的窗口对象的成员，并不是改写这个指针副本。可以联系上一章 [ptr] 修改 *ptr 的例子理解。
不能因此说“值捕获永远不会改变外部状态”。准确说法是：复制 int 后修改副本不会改变原 int；复制指针后，经指针访问的仍可能是同一个对象。
### 两个 this 扮演不同角色

connect(button, &QPushButton::clicked, this, [this]() {
    close();
});

第三个参数 this 是连接的上下文对象，参与自动断开和线程上下文选择；[this] 是 C++ Lambda 的捕获，让函数体能访问窗口成员。二者不能相互替代：有 context 不代表自动完成 C++ 捕获；有捕获也不代表自动建立 Qt 生命周期保护。参考6
### 不要把 this 当成窗口副本
[this] 不复制窗口，也不让窗口永远存活。对于异步保存的回调，要保证对象还存在；Qt 的带 context 连接会在 context 销毁时断开，但保护范围不包括任意捕获对象。
C++17 还有 [*this]，表示复制当前对象。QObject 及其子类通常不可复制，Widget 也不适合这样捕获。Qt 初学阶段优先使用显式 [this]，不依赖 [=] 隐式捕获 this。

把Lambda交给connect

先写出最小可用版本

auto *button = new QPushButton("点击", this);
connect(button, &QPushButton::clicked, this, []() {
    qDebug() << "按钮被按下";
});

这里不需要外部变量，因此捕获列表是 []。点击后，Qt 调用保存的函数对象；建立连接时不会执行日志。clicked 虽带 bool 参数，但这个 Lambda 不需要，便可以省略这个参数。
### 需要窗口成员时改成显式捕获

connect(button, &QPushButton::clicked, this, [this]() {
    setWindowTitle("已经点击");
});

判断捕获的方法是读函数体：如果只做独立计算或输出固定文本，可能 [] 就够；如果访问窗口成员，使用 [this]；如果只需要创建连接时的一段局部文字，使用 [text]；如果需要临时引用局部变量，先确认生命周期再写 [&value]。
### Lambda 为什么适合 Qt 初学
简单处理逻辑可以紧靠连接代码阅读，不必为了两行代码单独声明和实现一个槽函数。当处理流程变长、需要复用、需要单独测试时，应提取成成员函数，再由 Lambda 调用，或直接连接到该成员函数。

// 如果已经声明并实现 Widget::saveData()
connect(button, &QPushButton::clicked,
        this, &Widget::saveData);

上面是替代写法，不必同时保留两个连接。选择槽成员函数还是 Lambda，依据逻辑是否需要命名和复用，而不是认为某一种语法总是更高级。
### 四个参数版优先
初学时优先使用带 context 的四参数连接。它让连接跟随上下文对象的生命周期，也使回调执行的线程上下文更明确。即使如此，也要检查 Lambda 捕获的每个指针和引用。参考6
构造界面时常写“一个 new、一个设置属性、一个 connect”。把这些初始化步骤执行一次即可，不要在每次点击后又给同一个按钮不断追加连接。

参数适配与重载调用

信号给出的参数不一定就是业务参数

void requestFood(const QString &food)
{
    emit hungry(food);
}

在项目 5.4 或 5.19 的 Widget 构造函数中，使用下面的连接，让 Lambda 将 clicked 转为带菜名参数的调用。保留本次需要的连接，避免同一按钮重复连接。

auto *teacher = new Teacher(this);
auto *student = new Student(this);
auto *button = new QPushButton("请吃饭", this);

connect(teacher,
        qOverload<const QString &>(&Teacher::hungry),
        student,
        qOverload<const QString &>(&Student::treat));

connect(button, &QPushButton::clicked, this, [teacher]() {
    teacher->requestFood(QStringLiteral("红烧排骨"));
});

执行链是 clicked → Lambda → requestFood("红烧排骨") → hungry(food) → treat(food)。Lambda 不接收 checked，因为这里用不到它。teacher 被值捕获，复制的是指针，目标仍是那位老师。
本例 teacher 和 button 都由窗口管理，且不提前删除 teacher。若以后加入“单独删除老师”的功能，就需要重新检查连接的上下文和捕获指针，不能原样照搬生命周期假设。
### Lambda 可以把选择重载变成普通调用
如果需要调用 student 的带参 treat，可以写一个参数明确的 Lambda，再在里面调用 student->treat(food)。调用表达式有具体实参时，编译器可以按普通 C++ 重载规则选中版本。
不过发送端的重载信号仍要选清楚。Lambda 不是取消所有 qOverload 的开关；它主要让接收逻辑、参数转换、默认值填充等处理更直观。

延后执行与循环捕获

引用捕获了构造函数的局部变量

// 错误示意 构造函数结束后 count 不再存在
int count = 0;
connect(button, &QPushButton::clicked, this,
        [&count]() { ++count; });

修正方法：把状态放到 Widget 的成员 count_ 中，再用 [this] 访问。窗口还活着时，成员才存在；窗口销毁时，以它为 context 的连接也会断开。完整实现见下一章。
### 值捕获了循环变量 却以为会读取最终值

// 这段放在 Widget 构造函数中
for (int i = 0; i < 3; ++i) {
    auto *b = new QPushButton(QString::number(i), this);
    b->move(20, 20 + i * 50);
    connect(b, &QPushButton::clicked, this, [i]() {
        qDebug() << i;
    });
}

三个 Lambda 分别保存创建时的 i，点击按钮依次输出对应的 0、1、2。这正是想保留按钮编号时应有的行为。改成 [&i] 会让回调引用循环局部变量，循环结束后就失效，不能用这种方式实现编号。
### 定义了 Lambda 却没有调用它

auto work = []() { qDebug() << "开始处理"; };
work();  // 普通 C++ 场景 自己调用

connect(button, &QPushButton::clicked, this,
        []() { qDebug() << "开始处理"; });
// Qt 场景 等按钮发出信号时由 Qt 调用

把函数对象交给 connect 时，不要在 Lambda 后面加 () 去立即执行它。connect 需要收到“以后可以调用的行为”，不是收到这段行为现在执行后的结果。
### 每写一次捕获 都做一次检查
值捕获：我想保存创建时的值吗？引用捕获：这个变量会不会先消失？指针捕获：目标对象可能提前删除吗？this 捕获：有没有合适的 context，回调是否还被保存到其他地方？先回答这些问题，再选 [] 内的写法。

{
    QSaveFile file(path);
    if (!file.open(QIODevice::WriteOnly))
    {
        statusBar()->showMessage("无法保存：" + file.errorString());

本章要解决的问题

模态决定其他窗口能否接受输入；阻塞决定调用处代码是否等待返回。exec() 显示模态对话框并等待返回，它会运行嵌套事件循环，因此对话框本身仍能响应。open() 默认按窗口模态显示并立即返回，通常连接 finished、accepted 或 rejected 处理结果。show() 通常用于非模态显示，但也会受事先设置的 modality 属性影响。

局部栈对象 dialog.show() 一闪而过的根本原因是函数返回后对象立即析构。异步显示应让对象持续存在，例如 new QDialog(&w)，并设置 WA_DeleteOnClose。仅有 parent 能在父窗口销毁时回收，不等于每次关掉对话框立即回收。

是否模态和是否等待是两条轴

一个对话框可能限制其他窗口的输入，却不阻塞调用处代码。open 就属于这种情况。exec 等待结果，但内部仍继续处理对话框事件，所以“阻塞代码”不等于整个 GUI 线程停止工作。嵌套事件循环会带来重入，调用之前保存的对象状态可能在对话框打开期间被其他事件改变。

按执行顺序拆解

mainwindow.ui 提供入口按钮；dialog.ui 提供自定义 Dialog 的标签与标准按钮。点击入口后 new Dialog(this)，其构造函数加载自己的 .ui；设置 WA_DeleteOnClose 后调用 open。项目 7.2进一步对照 show/open/exec，区分窗口模态和调用是否等待。

参数与行为边界

栈对象不是永远不能用：局部 QDialog dialog; dialog.exec(); 可以活到 exec 返回。问题出在局部对象配 show/open 后函数马上返回。异步版本应使用能存活的对象，合理设置 parent 和 WA_DeleteOnClose。持有可能被关闭删除的指针时，可用 QPointer 检测对象是否仍存在。

易错点与排查

open() 和 show() 后不要让对象立即离开作用域。exec() 的栈对象可活到返回，但新代码通常优先考虑 open() 加结果信号，减少嵌套事件循环。对话框有 parent 仍可作为独立顶层对话框显示，不是普通嵌入控件。

本章要解决的问题

绝对定位要给控件逐个设置坐标和尺寸；布局则描述控件关系，由布局管理器在可用区域改变时重新安排。QHBoxLayout 从左到右，QVBoxLayout 从上到下，QGridLayout 按行列定位，QFormLayout 适合标签与输入框成对排列。

父布局用 addLayout 嵌入子布局，控件用 addWidget 加入。addStretch 放可伸缩空白；setContentsMargins 控制布局与外边界间距；setSpacing 控制相邻项目间距。stretch 是分配额外空间的权重，不是承诺最终宽高严格按比例分配，还会受 sizeHint、最小尺寸和 sizePolicy 约束。

布局管理的是空间约束

布局会综合 available space、sizeHint、minimumSize、maximumSize、sizePolicy 和 stretch 来分配空间。它不是简单把窗口按比例切成几个盒子。一个按钮即使 stretch 为 1，也可能由于样式或尺寸策略不愿竖向拉高；多行编辑器通常适合承担更多可伸缩空间。

本章要解决的问题

QPainter 执行画线、矩形、椭圆、图片和文本等操作；QPaintDevice 是可被绘制的设备基类；QPaintEngine 提供设备对应的绘制实现，入门通常不用直接操作。原笔记中的 QPainterDevice 应改为 QPaintDevice。

对 QWidget 绘制应在 paintEvent 或其调用链中完成。先创建 QPainter(this)，设置 QPen 控制边线颜色宽度，设置 QBrush 控制填充，再调用 drawLine、drawRect、drawEllipse。要改变图形，更新成员状态后调用 update() 请求重新绘制，而不是把绘图只放进按钮槽临时画一次。

QPixmap 常用于界面显示，QImage 便于像素访问，QBitmap 是一位深度位图，QPicture 记录与重放绘图命令。它们不是全部绘图设备，QWidget 也是 QPaintDevice 的子类。

图形应该从持久状态重建

绘制结果是窗口某一时刻的像素，不是可靠的应用状态。遮挡、缩放、主题变化等都可能触发重绘。把“画一个红椭圆”只写在按钮槽里而不保留颜色状态，下一次重绘可能消失。项目 11.2将 color_ 放在 DrawingArea 成员中，按钮只更新颜色并 update，paintEvent 每次根据状态重建图形。

按执行顺序拆解

mainwindow.ui 中 QWidget 已提升为 Canvas；mainwindow.cpp 只负责装载界面和状态提示。绘制逻辑独立在 canvas.cpp 的 paintEvent：创建局部 QPainter、设置画笔和画刷、绘制形状与文字，再绘制离屏 QImage。项目 11.2继续让绘制由成员状态驱动。

参数与行为边界

QWidget 是屏幕控件，QImage 便于像素操作，QPixmap 为界面显示优化，QBitmap 是一位位图，QPicture 记录绘制命令。逻辑坐标、像素坐标与设备像素比需要区分。painter.save/restore 可隔离画笔与坐标变换状态，复杂绘制中比反复手动恢复属性更可靠。

易错点与排查

QPicture 不是普通像素图片。QImage、QPixmap 上的离屏绘制可以在适当代码位置进行，不要求它们自己的 paintEvent。一个设备同时只应有一个活动画家；使用局部 QPainter 作用域可自动结束绘制。

遇到问题时先区分三个层次：编译错误检查声明、头文件与构建配置；界面无反应检查连接、接收对象与生存期；运行结果不对检查输入、返回值和分支是否真正执行。可以先在连接入口记录一条日志，再在结果处理处记录一条，定位中间哪一步没有到达。
