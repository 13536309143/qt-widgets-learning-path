第一章 Qt概述

先建立对 Qt、Qt Creator 和 Qt Widgets 的整体认识，再进入项目创建与具体控件。本教程按照当前学习内容组织成十一章，章节编号表示知识结构，示例编号表示独立项目。

1.1 Qt能做什么

Qt 是提供窗口、控件、对象通信、事件处理和绘图等能力的 C++ 框架。本教程使用 Qt Widgets 与 C++17，学习如何创建桌面窗口、响应用户操作，并把界面、对象状态和业务逻辑组织清楚。

界面并不是一张静态图片：程序先创建对象与窗口，再进入事件循环。用户点击按钮、输入文字或拖动窗口时，Qt 处理对应事件，并根据连接关系调用处理代码。

1.2 分清框架与开发工具

名称负责什么
Qt提供类、模块与运行所需的框架能力
Qt Widgets提供 QWidget、按钮、输入框、布局和桌面界面组件
Qt Creator编辑项目、配置 Kit、调用构建工具、运行与调试
编译器与链接器把 C++ 源码和需要的库构建成程序
qmake读取 .pro，生成构建规则
Designer编辑 .ui 中的控件、属性与布局

不要把 Qt Creator 当作编译器，也不要把 .pro 当作可执行文件。各工具如何协作，在第二章结合实际项目理解。

1.3 先认识几个基础类

QApplication 管理 GUI 应用的公共资源与事件处理；QObject 提供对象树和信号槽的基础；QWidget 是窗口与可视控件的基础；QMainWindow 提供主窗口框架；QDialog 用于对话式交互。后面的章节会逐一展开，不要求现在记住所有成员函数。

1.4 本教程的学习方法

每节先理解要解决的问题，再运行一个对应示例，阅读 .ui 和窗口类，预测修改结果，最后重新构建验证。遇到问题先区分编译失败、运行后没有反应、运行结果不符合预期，分别追踪构建配置、连接关系和数据变化。

2.1 创建Qt Widgets项目

在 Qt Creator 的新建项目向导中选择 Qt Widgets Application，填写名称和位置，构建系统选择 qmake。初学普通窗口时，类名使用 Widget，基类选择 QWidget，并保留生成表单的选项，得到 widget.ui。学习第六章主窗口时，再使用 MainWindow 与 QMainWindow。

向导的页面名称可能随版本变化，重点是选择 Widgets 项目、合适的基类、配套 Kit 和生成 .ui。完成后先构建运行，不要一开始同时修改多处配置。

2.2 Kit与构建配置

Kit 可以理解为一套配好的工具组合，包含 Qt 版本、编译器、调试器及目标设备等。Windows 上 MinGW 版 Qt 配套使用对应 MinGW 工具链，MSVC 版 Qt 配套使用相应 MSVC 工具链。

Debug 便于调试，Release 通常启用更多优化。遇到库格式或链接错误，先检查 Kit 和 Qt 是否匹配，再查源文件是否缺失。

2.3 默认模板文件的分工

文件负责什么
.pro列出 Qt 模块、C++ 标准、源文件、头文件、FORMS 和资源

widget.h / mainwindow.h声明窗口类、成员、槽和事件函数

2.4 程序入口的执行顺序

#include "widget.h"

#include <QApplication>

int main(int argc, char *argv[])
{
    QApplication a(argc, argv);
    Widget w;
    w.show();
    return QApplication::exec();
}

先创建 QApplication，再创建 Widget，这时执行窗口构造函数。show() 显示窗口，exec() 进入事件循环，程序才能继续响应点击、输入和重绘。若直接 return 0，程序很快结束；不需要自己写 while 循环来轮询按钮。

2.5 setupUi与ui指针

Widget::Widget(QWidget *parent)
    : QWidget(parent)
    , ui(new Ui::Widget)
{
    ui->setupUi(this);
}

Widget::~Widget()
{
    delete ui;
}

Ui::Widget 是生成的辅助类，不是窗口本身。setupUi(this) 执行后才建立控件和布局，因此访问 ui->控件 要放在它之后。delete ui 释放辅助对象；控件对象主要由 QObject 父子关系管理。

控件的 objectName 决定生成的成员名，text 只是显示文字。修改 .ui 后应保存并重新构建，不要直接修改 ui_widget.h 或 ui_mainwindow.h。统一模板与 Designer 操作 提供完整说明。

2.6 Designer 与 setupUi

对应示例：完整源码。先运行项目观察行为，再按以下顺序阅读。

2.6.1 本章要解决的问题

Designer 将界面保存在 .ui XML 文件中，构建时 uic 生成 ui_mainwindow.h。mainwindow.h 用前向声明保存 Ui::MainWindow *ui；mainwindow.cpp 包含生成的头文件，在构造函数中创建辅助对象、调用 ui->setupUi(this)，在析构函数中 delete ui。

objectName 是代码成员和自动连接所依赖的对象名，text 是显示文字。按钮名为 runButton，槽名为 on_runButton_clicked，且在 private slots 中声明，因此 setupUi 会自动完成连接。

2.6.2 默认模板与自动连接

本步 main.cpp 与 Qt Creator 默认模板一致，只启动 MainWindow。控件和布局都在 mainwindow.ui，行为写在 mainwindow.cpp。不要修改 ui_mainwindow.h，也不要对已自动连接的槽再 connect 一次。Designer 中“转到槽”会帮你生成相应声明和实现。

2.6.3 按执行顺序拆解

main.cpp 创建 MainWindow。mainwindow.h 声明 Ui::MainWindow *ui 和 on_runButton_clicked 槽；mainwindow.cpp 在初始化列表创建 Ui 辅助对象，再调用 ui->setupUi(this)。这个调用会建立 .ui 中的控件并自动连接 runButton 的 clicked 信号。点击后只执行对应槽，析构时 delete ui。

2.6.4 参数与行为边界

Qt Creator 向导常用 Ui::MainWindow *ui；new 出来的包装器需要 delete ui。这个 delete 释放包装器，不是要求你手动逐个 delete 其所有子控件。ui_*.h 每次构建可能重新生成，不应手动修补它来解决错误。

2.6.5 易错点与排查

不要手动改 ui_mainwindow.h，重新构建会覆盖。应该改 mainwindow.ui 或自己的 .cpp。QMainWindow 的布局要放在 centralwidget 上。示例提供真实 .ui，可直接在 Qt Creator 中双击打开。

遇到问题时先区分三个层次：编译错误检查声明、头文件与构建配置；界面无反应检查连接、接收对象与生存期；运行结果不对检查输入、返回值和分支是否真正执行。可以先在连接入口记录一条日志，再在结果处理处记录一条，定位中间哪一步没有到达。

3.2 初始尺寸与固定尺寸

resize(w, h) 通常仍允许继续调整尺寸；setFixedSize(w, h) 则把最小、最大尺寸限制为相同数值。示例 02 先使用可调整的窗口，再通过按钮固定为 720 × 540，便于对照观察。

3.3 资源路径 图片与背景

对应示例：完整源码。先运行项目观察行为，再按以下顺序阅读。

3.3.1 本章要解决的问题

qrc 是资源清单，prefix 是资源前缀，alias 是资源在程序里的名字。例如前缀 /images 加别名 demo.png，运行时路径为 :/images/demo.png。这个路径与程序当前工作目录无关。qmake 项目还需要 RESOURCES += assets.qrc，构建时 rcc 才会把资源编入程序。

QPixmap 加载失败时 isNull() 为 true，先检查路径大小写、前缀、别名以及资源是否加入构建。QLabel 显示图片时，按目标区域调用 scaled(..., Qt::KeepAspectRatio, Qt::SmoothTransformation) 可以等比适应。若要做随窗口变化的背景，在 paintEvent 中基于当前 rect 绘制更直接；构造时只缩放一次不会跟随未来窗口变化。

3.3.2 磁盘路径 资源路径和显示尺寸

磁盘文件依赖部署位置和文件权限，:/ 开头的资源路径指向 Qt 资源系统。qrc 用 prefix 与 alias 构成运行时名字；XML 中 file 的内容是构建时要读取的源文件位置。因此“源码磁盘文件名”和“程序访问名字”可以不同，改了 alias 后代码也要同步。

3.3.3 按执行顺序拆解

先打开 assets.qrc 确认 prefix、alias 与素材，再打开 mainwindow.ui 查看 imageLabel。mainwindow.cpp 用资源路径读取 QPixmap，失败时显示提示，成功时设置缩放后的图像，并用同一资源设置窗口图标。资源由构建系统打包，不依赖运行工作目录。

3.3.4 参数与行为边界

isNull 用于检查图片是否加载成功。Q_ASSERT 常在 Release 被关闭，不能把生产错误处理只写成断言；要用普通 if 处理并提示。scaled 返回新图片，不会原地修改原对象。KeepAspectRatio 保持比例，KeepAspectRatioByExpanding 会铺满但可能裁剪，IgnoreAspectRatio 可能变形。

3.3.5 易错点与排查

Qt 6 中 QPalette::Window 是窗口背景角色。用图片刷填充可能出现平铺；IgnoreAspectRatio 会拉伸变形。资源文件通常打包进程序，但资源系统也支持外部 rcc，并非所有资源都必须内嵌。

遇到问题时先区分三个层次：编译错误检查声明、头文件与构建配置；界面无反应检查连接、接收对象与生存期；运行结果不对检查输入、返回值和分支是否真正执行。可以先在连接入口记录一条日志，再在结果处理处记录一条，定位中间哪一步没有到达。

3.3 资源路径 图片与背景

本章要解决的问题

qrc 是资源清单，prefix 是资源前缀，alias 是资源在程序里的名字。例如前缀 /images 加别名 demo.png，运行时路径为 :/images/demo.png。这个路径与程序当前工作目录无关。qmake 项目还需要 RESOURCES += assets.qrc，构建时 rcc 才会把资源编入程序。

QPixmap 加载失败时 isNull() 为 true，先检查路径大小写、前缀、别名以及资源是否加入构建。QLabel 显示图片时，按目标区域调用 scaled(..., Qt::KeepAspectRatio, Qt::SmoothTransformation) 可以等比适应。若要做随窗口变化的背景，在 paintEvent 中基于当前 rect 绘制更直接；构造时只缩放一次不会跟随未来窗口变化。

磁盘路径 资源路径和显示尺寸

磁盘文件依赖部署位置和文件权限，:/ 开头的资源路径指向 Qt 资源系统。qrc 用 prefix 与 alias 构成运行时名字；XML 中 file 的内容是构建时要读取的源文件位置。因此“源码磁盘文件名”和“程序访问名字”可以不同，改了 alias 后代码也要同步。

按执行顺序拆解

先打开 assets.qrc 确认 prefix、alias 与素材，再打开 mainwindow.ui 查看 imageLabel。mainwindow.cpp 用资源路径读取 QPixmap，失败时显示提示，成功时设置缩放后的图像，并用同一资源设置窗口图标。资源由构建系统打包，不依赖运行工作目录。

参数与行为边界

isNull 用于检查图片是否加载成功。Q_ASSERT 常在 Release 被关闭，不能把生产错误处理只写成断言；要用普通 if 处理并提示。scaled 返回新图片，不会原地修改原对象。KeepAspectRatio 保持比例，KeepAspectRatioByExpanding 会铺满但可能裁剪，IgnoreAspectRatio 可能变形。

易错点与排查

Qt 6 中 QPalette::Window 是窗口背景角色。用图片刷填充可能出现平铺；IgnoreAspectRatio 会拉伸变形。资源文件通常打包进程序，但资源系统也支持外部 rcc，并非所有资源都必须内嵌。

遇到问题时先区分三个层次：编译错误检查声明、头文件与构建配置；界面无反应检查连接、接收对象与生存期；运行结果不对检查输入、返回值和分支是否真正执行。可以先在连接入口记录一条日志，再在结果处理处记录一条，定位中间哪一步没有到达。

先理解对象怎样通过信号槽通信，再逐步学习 Lambda。Lambda 是本章内部的一组连续小节，按语法、捕获、状态、生存期、实际按钮回调的顺序展开。

5.1 信号和槽的基本连接

5.1.1 把事件和处理代码连起来

auto *button = new QPushButton("关闭窗口", this);
connect(button, &QPushButton::clicked,
        this, &QWidget::close);

这行代码可以读成：button 发出 clicked 时，调用当前窗口的 close。connect 建立连接时不会立刻关闭窗口；真正触发 clicked 后才调用处理函数。&QPushButton::clicked 是成员函数指针，写连接时不加 ()，否则就变成调用函数。
### 5.1.2 四个位置怎样记

connect(发送对象, &发送类::信号,
        接收对象, &接收类::处理函数);

前两个参数回答“谁发出什么通知”，后两个参数回答“由哪个对象执行哪个函数”。在 Widget 成员函数中可以直接写 connect；在普通函数如 main 中通常写 QObject::connect。
clicked 的签名含 bool checked 参数，而 close() 不接收参数。这仍可连接，因为处理函数可以忽略信号末尾的参数。函数指针连接要求对应参数兼容，可存在允许的隐式类型转换；不能把不兼容的参数强行连起来。参考6
### 5.1.3 槽函数并不都必须返回 void
自定义信号通常声明为 void；槽是普通 C++ 函数，可以有返回值。但普通信号通知不用于收集槽的返回值。例如 QWidget::close() 返回 bool，也能作为这里的处理函数。入门自定义槽写成 void 最直观。
新式 connect 可以连接普通成员函数，也可以连接 Lambda 等可调用对象。若要声明传统元对象槽，可放在 public slots: 或 private slots: 下；不是所有被连接的成员函数都必须写在 slots 区域。参考7
### 5.1.4 一次信号与多个处理函数
可以一对多、多对一，也可以信号连接信号。同线程直接连接时，同一信号连接的多个处理函数按建立连接的顺序调用。跨线程或队列连接涉及事件投递，不应据此推断不同线程中处理完成的先后顺序。参考6参考7

5.3 重载信号与断开连接

5.3.1 为什么重载必须指定版本

// 在拥有 teacher 和 student 的作用域中
connect(teacher,
        qOverload<const QString &>(&Teacher::hungry),
        student,
        qOverload<const QString &>(&Student::treat));

qOverload<>() 选择无参版本；qOverload<const QString &>() 选择参数为 const QString & 的版本。这里模板参数必须与函数真实声明相符，不能把 QString 与 const QString & 当成同一个成员函数类型。
原笔记使用成员函数指针变量的思路也成立：

void (Teacher::*sig)(const QString &) = &Teacher::hungry;
void (Student::*slot)(const QString &) = &Student::treat;
connect(teacher, sig, student, slot);

左边从中间读：sig 是 Teacher 类的成员函数指针，该函数接收 const QString &，返回 void。qOverload 只是让选择版本的表达更紧凑，两个示例是替代写法，不要重复连接。
### 5.3.2 保存连接句柄再断开

QMetaObject::Connection c = connect(
    teacher, qOverload<>(&Teacher::hungry),
    student, qOverload<>(&Student::treat));

QObject::disconnect(c);

disconnect 是函数，不是 C++ 关键字。保存返回的句柄，能准确断开这一条连接，尤其适合 Lambda。句柄变量离开作用域本身不会自动断开连接。参考6
发送者或接收者销毁时，相关连接会被自动清理。Lambda 使用带 context 的 connect 时，context 销毁也会使该连接断开；但 Lambda 捕获的其他对象是否仍然存活，仍要自己保证。
### 5.3.3 重复输出不一定是信号发了两次
同一条连接代码执行两次，默认会建立两条连接，信号发出一次也可能让处理函数运行两次。优先检查初始化函数是否重复调用，避免在反复进入的函数中不断 connect。Qt::UniqueConnection 有适用限制，不能当成所有 Lambda 连接的通用去重开关。参考6

5.4 Lambda的基本结构与调用

5.4.1 它解决什么问题

int add(int a, int b)
{
    return a + b;
}
int result = add(3, 4);  // result 为 7

改写成 Lambda 后：

auto add = [](int a, int b) -> int {
    return a + b;
};
int result = add(3, 4);  // 仍然为 7

auto 让编译器推导 add 的类型。Lambda 产生的是一个可调用的函数对象，可用 add(...) 调用；它不只是“没有名字的普通函数”。结尾的分号结束变量定义，不能漏掉。
### 5.4.2 一段语法分成五部分

[捕获列表](参数列表) mutable -> 返回值类型 {
    函数体
}

捕获列表回答“如何使用外部局部变量”；参数列表回答“调用时需要传什么”；mutable 决定是否允许修改值捕获的副本；返回类型回答“返回什么”；函数体写实际执行的语句。参考8
最开始只用最简单的 []() { ... }。不要把 mutable 和返回类型当成每次必填的内容。返回类型通常可以由 return 推导，上面的 -> int 可以省略。
### 5.4.3 定义和执行是两件事

auto say = []() { qDebug() << "你好"; };
// 到这里还没有输出
say();  // 此时才执行函数体并输出

写出 Lambda 只是创建可调用对象。调用 say() 才运行它的函数体。connect 中也是先登记这段行为，等信号触发后再执行。

5.5 捕获列表和参数列表

5.5.1 先看变量是从哪里来的

int base = 10;
auto addBase = [base](int x) {
    return base + x;
};
qDebug() << addBase(3);  // 13
qDebug() << addBase(8);  // 18

base 在 Lambda 外部定义，创建 Lambda 时通过 [base] 保存一个副本。x 是每次调用时传入的参数，addBase(3) 中 x 是 3，addBase(8) 中 x 是 8。二者都能在函数体里使用，但来源和进入函数体的时间不同。
| 观察点 | 捕获列表 [base] | 参数列表 (int x) |
| --- | --- | --- |
| 数据来源 | 外部作用域中已有的局部变量 | 调用者本次提供的实参 |
| 进入时机 | 创建 Lambda 时建立捕获 | 每次调用时初始化参数 |
| 外面怎样写 | [base] 或 [&base] 等 | addBase(3) 中的 3 |
| 主要用途 | 保留这段行为所需的上下文 | 处理每次调用不同的输入 |
### 5.5.2 没捕获就不能随便用外面的局部变量

int base = 10;
// 错误示意 base 是外部自动存储期局部变量
// auto f = [](int x) { return base + x; };

auto f = [base](int x) { return base + x; }; // 正确

[] 表示没有捕获，不等于函数体什么都不能做。它仍能使用自己的参数、函数体内新建的局部变量，以及无需捕获就可访问的全局变量或静态变量等。
### 5.5.3 Qt 中两种来源同时出现

QString tag = "保存按钮";
connect(button, &QPushButton::clicked, this,
        [tag](bool checked) {
    qDebug() << tag << checked;
});

tag 来自创建连接时所在的作用域；checked 来自按钮每次发出的信号。不要把 checked 也写进捕获列表来替代参数，那会改变它的数据来源。普通按钮默认不可勾选，若要观察 checked 切换，可先 button->setCheckable(true)。

5.6 值捕获与指针捕获

5.6.1 外面的值改变 副本不会跟着改变

int n = 10;
auto read = [n]() { return n; };
n = 20;
qDebug() << read();  // 10
qDebug() << n;       // 20

执行到 [n] 时，Lambda 保存了当时 n 的值 10。之后 n = 20 修改的是外面的变量。调用 read() 读取的是自己的副本，因此结果仍然是 10。
可以把值捕获理解为“拍下当时的值”，但这只是帮助理解的比喻：实际复制什么、复制后共享什么，由被捕获类型自己的复制语义决定。对 int 而言就是保存一个独立数值。
### 5.6.2 默认不能给值捕获的普通变量赋值

int n = 10;
auto read = [n]() {
    // n = 30;  // 编译失败 当前不能修改这个副本
    return n;
};

这是 Lambda 默认调用运算符的 const 限制。之后可以用 mutable 允许修改副本，但 mutable 不会把值捕获变成引用捕获。参考8
### 5.6.3 捕获指针复制的是地址

int number = 10;
int *ptr = &number;
auto change = [ptr]() { *ptr = 30; };
change();
qDebug() << number;  // 30

副本 ptr 和外面的 ptr 都指向同一个 number。虽然复制了指针，但没有复制它指向的 int。*ptr = 30 改变目标对象，所以外部 number 也变了。这也解释了为什么捕获 this 后可以修改窗口成员。
值捕获不自动延长指针目标的生命。如果捕获的是某个 QWidget*，后面控件先被删除，再使用这个地址仍然危险。学习时要分别问两件事：“复制了什么”和“目标对象还活着吗”。
### 5.6.4 什么时候适合值捕获
希望保存创建连接时的一段文字、一个编号或一个固定配置时，可以显式值捕获。例如 [tag] 比默认 [=] 更容易看清这段代码依赖了什么。需要读取不断变化的状态时，应考虑引用或对象成员，而不是误以为旧副本会自动更新。

5.7 引用捕获与生命周期

5.7.1 修改会反映到外部

int n = 10;
auto increase = [&n]() { ++n; };
increase();
qDebug() << n;  // 11
n = 40;
increase();
qDebug() << n;  // 41

[&n] 让函数体通过引用访问外面的 n，因而既能看到外部后续变化，也能修改外部值。这种修改不需要 mutable，因为修改的不是值捕获副本。
### 5.7.2 看懂常见捕获写法
| 写法 | 含义 |
| --- | --- |
| [] | 不捕获外部局部变量 |
| [n] | 按值捕获 n |
| [&n] | 按引用捕获 n |
| [n &m] 的正确写法为 [n, &m] | n 用副本 m 用引用 |
| [=] | 对需要捕获的外部局部变量默认按值捕获 |
| [&] | 对需要捕获的外部局部变量默认按引用捕获 |
| [this] | 保存当前对象的 this 指针 可访问对象成员 |
混合捕获时，逗号分隔每一项。入门优先把所需变量显式写出来，例如 [count, &total]，便于发现外部依赖。默认捕获不等于无条件捕获所在作用域的一切。参考8
### 5.7.3 最大的风险是变量已经不存在

// 错误示意 不要这样给按钮长期保存回调
void Widget::setupButton()
{
    int count = 0;
    auto *button = new QPushButton("计数", this);
    connect(button, &QPushButton::clicked, this,
            [&count]() { ++count; });
}

setupButton() 返回后，局部 count 已结束生命周期。按钮以后被点击时才执行 Lambda，这时引用已经悬空，访问它属于未定义行为。即使 connect 写了 this 作为上下文，也不能保护这个局部 count。

5.8 mutable与副本状态

5.8.1 拆解原来的例子

int m = 10;
auto fun = [m](int a, int b) mutable {
    qDebug() << "lambda is running!";
    m = 300;
    return a + b;
};
int sum = fun(100, 200);
qDebug() << sum;
qDebug() << m;

依次输出的内容是 lambda is running!、300、10。第一行来自函数体的日志；第二行的 300 是 a + b 的返回值；第三行的 10 来自外部 m。注意这里“内部 m 被赋为 300”和“返回值也是 300”只是数值恰好相同，没有因果关系。
执行过程：① 外部 m 初始化为 10。② [m] 复制 10 进入函数对象。③ mutable 允许给内部副本重新赋值。④ 调用时 a 为 100，b 为 200。⑤ m = 300 改变内部副本。⑥ return a + b 返回 300。⑦ 外部 m 始终没有改变。
### 5.8.2 改写一下 就能看出副本会保留

int m = 10;
auto next = [m]() mutable { return ++m; };
qDebug() << next();  // 11
qDebug() << next();  // 12
qDebug() << m;       // 10

对同一个 next 对象连续调用，使用的是同一个内部副本，所以从 10 增到 11，再增到 12，并不是每次调用都重新从外部复制 10。创建 Lambda 和调用 Lambda 要分开理解。
### 5.8.3 如果想改变外面的 m

int m = 10;
auto next = [&m]() { return ++m; };
qDebug() << next();  // 11
qDebug() << m;       // 11

这里使用引用捕获，不需要 mutable。记忆时分开两条：值或引用决定“访问的是副本还是外部变量”；mutable 决定“能否修改值捕获副本”。它们解决的是不同问题。
本笔记采用 C++17，带 mutable 的 Lambda 保留空参数列表 ()，写作 [m]() mutable { ... }。这样也能避免混淆不同 C++ 标准下的省略规则。

5.9 this与窗口成员

5.9.1 this 本来就是一个指针

// widget.h 中 Widget 类的 private 区域
int count_ = 0;

// Widget 构造函数中
auto *button = new QPushButton("点击计数", this);
connect(button, &QPushButton::clicked, this, [this]() {
    ++count_;
    setWindowTitle(QString("已点击 %1 次").arg(count_));
});

count_ 等价于 this->count_，setWindowTitle(...) 等价于 this->setWindowTitle(...)。通过保存的 this 指针访问当前窗口，所以不需要把每个成员都单独放进捕获列表。
### 5.9.2 为什么不用 mutable 也能修改成员
[this] 保存的是 this 指针，修改的是它指向的窗口对象的成员，并不是改写这个指针副本。可以联系上一章 [ptr] 修改 *ptr 的例子理解。
不能因此说“值捕获永远不会改变外部状态”。准确说法是：复制 int 后修改副本不会改变原 int；复制指针后，经指针访问的仍可能是同一个对象。
### 5.9.3 两个 this 扮演不同角色

connect(button, &QPushButton::clicked, this, [this]() {
    close();
});

第三个参数 this 是连接的上下文对象，参与自动断开和线程上下文选择；[this] 是 C++ Lambda 的捕获，让函数体能访问窗口成员。二者不能相互替代：有 context 不代表自动完成 C++ 捕获；有捕获也不代表自动建立 Qt 生命周期保护。参考6
### 5.9.4 不要把 this 当成窗口副本
[this] 不复制窗口，也不让窗口永远存活。对于异步保存的回调，要保证对象还存在；Qt 的带 context 连接会在 context 销毁时断开，但保护范围不包括任意捕获对象。
C++17 还有 [*this]，表示复制当前对象。QObject 及其子类通常不可复制，Widget 也不适合这样捕获。Qt 初学阶段优先使用显式 [this]，不依赖 [=] 隐式捕获 this。

5.10 把Lambda交给connect

5.10.1 先写出最小可用版本

auto *button = new QPushButton("点击", this);
connect(button, &QPushButton::clicked, this, []() {
    qDebug() << "按钮被按下";
});

这里不需要外部变量，因此捕获列表是 []。点击后，Qt 调用保存的函数对象；建立连接时不会执行日志。clicked 虽带 bool 参数，但这个 Lambda 不需要，便可以省略这个参数。
### 5.10.2 需要窗口成员时改成显式捕获

connect(button, &QPushButton::clicked, this, [this]() {
    setWindowTitle("已经点击");
});

判断捕获的方法是读函数体：如果只做独立计算或输出固定文本，可能 [] 就够；如果访问窗口成员，使用 [this]；如果只需要创建连接时的一段局部文字，使用 [text]；如果需要临时引用局部变量，先确认生命周期再写 [&value]。
### 5.10.3 Lambda 为什么适合 Qt 初学
简单处理逻辑可以紧靠连接代码阅读，不必为了两行代码单独声明和实现一个槽函数。当处理流程变长、需要复用、需要单独测试时，应提取成成员函数，再由 Lambda 调用，或直接连接到该成员函数。

// 如果已经声明并实现 Widget::saveData()
connect(button, &QPushButton::clicked,
        this, &Widget::saveData);

上面是替代写法，不必同时保留两个连接。选择槽成员函数还是 Lambda，依据逻辑是否需要命名和复用，而不是认为某一种语法总是更高级。
### 5.10.4 四个参数版优先
初学时优先使用带 context 的四参数连接。它让连接跟随上下文对象的生命周期，也使回调执行的线程上下文更明确。即使如此，也要检查 Lambda 捕获的每个指针和引用。参考6
构造界面时常写“一个 new、一个设置属性、一个 connect”。把这些初始化步骤执行一次即可，不要在每次点击后又给同一个按钮不断追加连接。

5.11 参数适配与重载调用

5.11.1 信号给出的参数不一定就是业务参数

void requestFood(const QString &food)
{
    emit hungry(food);
}

在示例 09 或 24 的 Widget 构造函数中，使用下面的连接，让 Lambda 将 clicked 转为带菜名参数的调用。保留本次需要的连接，避免同一按钮重复连接。

auto *teacher = new Teacher(this);
auto *student = new Student(this);
auto *button = new QPushButton("请吃饭", this);

connect(teacher,
        qOverload<const QString &>(&Teacher::hungry),
        student,
        qOverload<const QString &>(&Student::treat));

connect(button, &QPushButton::clicked, this, [teacher]() {
    teacher->requestFood(QStringLiteral("红烧排骨"));
});

执行链是 clicked → Lambda → requestFood("红烧排骨") → hungry(food) → treat(food)。Lambda 不接收 checked，因为这里用不到它。teacher 被值捕获，复制的是指针，目标仍是那位老师。
本例 teacher 和 button 都由窗口管理，且不提前删除 teacher。若以后加入“单独删除老师”的功能，就需要重新检查连接的上下文和捕获指针，不能原样照搬生命周期假设。
### 5.11.2 Lambda 可以把选择重载变成普通调用
如果需要调用 student 的带参 treat，可以写一个参数明确的 Lambda，再在里面调用 student->treat(food)。调用表达式有具体实参时，编译器可以按普通 C++ 重载规则选中版本。
不过发送端的重载信号仍要选清楚。Lambda 不是取消所有 qOverload 的开关；它主要让接收逻辑、参数转换、默认值填充等处理更直观。

5.12 延后执行与循环捕获

5.12.1 引用捕获了构造函数的局部变量

// 错误示意 构造函数结束后 count 不再存在
int count = 0;
connect(button, &QPushButton::clicked, this,
        [&count]() { ++count; });

修正方法：把状态放到 Widget 的成员 count_ 中，再用 [this] 访问。窗口还活着时，成员才存在；窗口销毁时，以它为 context 的连接也会断开。完整实现见下一章。
### 5.12.2 值捕获了循环变量 却以为会读取最终值

// 这段放在 Widget 构造函数中
for (int i = 0; i < 3; ++i) {
    auto *b = new QPushButton(QString::number(i), this);
    b->move(20, 20 + i * 50);
    connect(b, &QPushButton::clicked, this, [i]() {
        qDebug() << i;
    });
}

三个 Lambda 分别保存创建时的 i，点击按钮依次输出对应的 0、1、2。这正是想保留按钮编号时应有的行为。改成 [&i] 会让回调引用循环局部变量，循环结束后就失效，不能用这种方式实现编号。
### 5.12.3 定义了 Lambda 却没有调用它

auto work = []() { qDebug() << "开始处理"; };
work();  // 普通 C++ 场景 自己调用

connect(button, &QPushButton::clicked, this,
        []() { qDebug() << "开始处理"; });
// Qt 场景 等按钮发出信号时由 Qt 调用

把函数对象交给 connect 时，不要在 Lambda 后面加 () 去立即执行它。connect 需要收到“以后可以调用的行为”，不是收到这段行为现在执行后的结果。
### 5.12.4 每写一次捕获 都做一次检查
值捕获：我想保存创建时的值吗？引用捕获：这个变量会不会先消失？指针捕获：目标对象可能提前删除吗？this 捕获：有没有合适的 context，回调是否还被保存到其他地方？先回答这些问题，再选 [] 内的写法。

### 5.14.4 Qt 场景答案
题目四：connect 只是保存回调，构造函数返回前不一定触发点击。等用户点击时，局部 count 已结束生命周期，引用失效。把计数改成 Widget 的成员 int count_ = 0;，然后以窗口为 context，使用 [this] 访问。
题目五：第三个 this 是 Qt 的 context，窗口销毁时相关连接会自动断开；[this] 是 C++ 捕获，让函数体能够访问窗口成员。删除捕获而保留 [] 时，这里的 setWindowTitle() 缺少可用的当前对象，不能这样调用。
题目六：在 teacher 和 button 已经创建、并保证 teacher 在回调执行时仍然存活的前提下：

### 5.14.5 遇到新 Lambda 时的阅读顺序
先看函数体，确定它要做什么；再看参数列表，确定每次输入来自哪里；然后看捕获列表，确认外部依赖的来源与生命期；最后找调用位置，区分立即调用、保存后调用、由 Qt 信号触发调用。
如果读不懂复杂写法，可以先把它保存为 auto task = ...，再单独写 task(...) 测试普通 C++ 行为。理解后再放回 connect，不必同时理解所有语法和事件机制。

6.3.1 本章要解决的问题

6.3.2 状态反馈和辅助面板各有职责

状态栏回答“现在发生了什么”，停靠面板提供持续可操作的辅助区。showMessage 的临时文字适合“打开成功”，普通状态控件适合当前工具，永久状态控件适合编码或连接状态。showMessage 的超时单位是毫秒；传 3000 表示约三秒，不是三千秒。

7.1 模态 非模态与对象生命期

对应示例：完整源码。先运行项目观察行为，再按以下顺序阅读。

7.1.1 本章要解决的问题

模态决定其他窗口能否接受输入；阻塞决定调用处代码是否等待返回。exec() 显示模态对话框并等待返回，它会运行嵌套事件循环，因此对话框本身仍能响应。open() 默认按窗口模态显示并立即返回，通常连接 finished、accepted 或 rejected 处理结果。show() 通常用于非模态显示，但也会受事先设置的 modality 属性影响。

局部栈对象 dialog.show() 一闪而过的根本原因是函数返回后对象立即析构。异步显示应让对象持续存在，例如 new QDialog(&w)，并设置 WA_DeleteOnClose。仅有 parent 能在父窗口销毁时回收，不等于每次关掉对话框立即回收。

7.1.2 是否模态和是否等待是两条轴

一个对话框可能限制其他窗口的输入，却不阻塞调用处代码。open 就属于这种情况。exec 等待结果，但内部仍继续处理对话框事件，所以“阻塞代码”不等于整个 GUI 线程停止工作。嵌套事件循环会带来重入，调用之前保存的对象状态可能在对话框打开期间被其他事件改变。

7.1.3 按执行顺序拆解

mainwindow.ui 提供入口按钮；dialog.ui 提供自定义 Dialog 的标签与标准按钮。点击入口后 new Dialog(this)，其构造函数加载自己的 .ui；设置 WA_DeleteOnClose 后调用 open。示例 50进一步对照 show/open/exec，区分窗口模态和调用是否等待。

7.1.4 参数与行为边界

栈对象不是永远不能用：局部 QDialog dialog; dialog.exec(); 可以活到 exec 返回。问题出在局部对象配 show/open 后函数马上返回。异步版本应使用能存活的对象，合理设置 parent 和 WA_DeleteOnClose。持有可能被关闭删除的指针时，可用 QPointer 检测对象是否仍存在。

7.1.5 易错点与排查

open() 和 show() 后不要让对象立即离开作用域。exec() 的栈对象可活到返回，但新代码通常优先考虑 open() 加结果信号，减少嵌套事件循环。对话框有 parent 仍可作为独立顶层对话框显示，不是普通嵌入控件。

遇到问题时先区分三个层次：编译错误检查声明、头文件与构建配置；界面无反应检查连接、接收对象与生存期；运行结果不对检查输入、返回值和分支是否真正执行。可以先在连接入口记录一条日志，再在结果处理处记录一条，定位中间哪一步没有到达。

7.1 模态 非模态与对象生命期

对应示例：完整源码。先运行项目观察行为，再按以下顺序阅读。

本章要解决的问题

模态决定其他窗口能否接受输入；阻塞决定调用处代码是否等待返回。exec() 显示模态对话框并等待返回，它会运行嵌套事件循环，因此对话框本身仍能响应。open() 默认按窗口模态显示并立即返回，通常连接 finished、accepted 或 rejected 处理结果。show() 通常用于非模态显示，但也会受事先设置的 modality 属性影响。

局部栈对象 dialog.show() 一闪而过的根本原因是函数返回后对象立即析构。异步显示应让对象持续存在，例如 new QDialog(&w)，并设置 WA_DeleteOnClose。仅有 parent 能在父窗口销毁时回收，不等于每次关掉对话框立即回收。

是否模态和是否等待是两条轴

一个对话框可能限制其他窗口的输入，却不阻塞调用处代码。open 就属于这种情况。exec 等待结果，但内部仍继续处理对话框事件，所以“阻塞代码”不等于整个 GUI 线程停止工作。嵌套事件循环会带来重入，调用之前保存的对象状态可能在对话框打开期间被其他事件改变。

按执行顺序拆解

mainwindow.ui 提供入口按钮；dialog.ui 提供自定义 Dialog 的标签与标准按钮。点击入口后 new Dialog(this)，其构造函数加载自己的 .ui；设置 WA_DeleteOnClose 后调用 open。示例 50进一步对照 show/open/exec，区分窗口模态和调用是否等待。

参数与行为边界

栈对象不是永远不能用：局部 QDialog dialog; dialog.exec(); 可以活到 exec 返回。问题出在局部对象配 show/open 后函数马上返回。异步版本应使用能存活的对象，合理设置 parent 和 WA_DeleteOnClose。持有可能被关闭删除的指针时，可用 QPointer 检测对象是否仍存在。

易错点与排查

open() 和 show() 后不要让对象立即离开作用域。exec() 的栈对象可活到返回，但新代码通常优先考虑 open() 加结果信号，减少嵌套事件循环。对话框有 parent 仍可作为独立顶层对话框显示，不是普通嵌入控件。

本章要解决的问题

8.1.1 本章要解决的问题

绝对定位要给控件逐个设置坐标和尺寸；布局则描述控件关系，由布局管理器在可用区域改变时重新安排。QHBoxLayout 从左到右，QVBoxLayout 从上到下，QGridLayout 按行列定位，QFormLayout 适合标签与输入框成对排列。

父布局用 addLayout 嵌入子布局，控件用 addWidget 加入。addStretch 放可伸缩空白；setContentsMargins 控制布局与外边界间距；setSpacing 控制相邻项目间距。stretch 是分配额外空间的权重，不是承诺最终宽高严格按比例分配，还会受 sizeHint、最小尺寸和 sizePolicy 约束。

8.1.2 布局管理的是空间约束

布局会综合 available space、sizeHint、minimumSize、maximumSize、sizePolicy 和 stretch 来分配空间。它不是简单把窗口按比例切成几个盒子。一个按钮即使 stretch 为 1，也可能由于样式或尺寸策略不愿竖向拉高；多行编辑器通常适合承担更多可伸缩空间。

8.1.3 按执行顺序拆解

打开 mainwindow.ui，在 centralwidget 下找到 verticalLayout，内部依次是 formLayout、gridLayout 和 buttonLayout。表单项设置 row/column，网格放置六个按钮，底部水平布局包含伸缩占位和确定/取消按钮。外层边距为 20、spacing 为 14。C++ 不重复创建布局。

8.1.4 参数与行为边界

contentsMargins 是容器内缘留白，spacing 是相邻项目间隔，addSpacing 是固定间隔，addStretch 是可伸缩空白。QGridLayout 的 rowSpan 和 columnSpan 允许跨行列。QFormLayout 不等于 QTableWidget：前者安排控件，后者显示可编辑表格数据。

8.1.5 易错点与排查

布局不是可见控件。控件加入布局后不要再依赖 move()/resize() 固定摆放。不要给同一 QWidget 安装两个顶层布局；QMainWindow 先设置 centralWidget，再给这个容器安装布局。

父布局用 addLayout 嵌入子布局，控件用 addWidget 加入。addStretch 放可伸缩空白；setContentsMargins 控制布局与外边界间距；setSpacing 控制相邻项目间距。stretch 是分配额外空间的权重，不是承诺最终宽高严格按比例分配，还会受 sizeHint、最小尺寸和 sizePolicy 约束。

布局管理的是空间约束

布局会综合 available space、sizeHint、minimumSize、maximumSize、sizePolicy 和 stretch 来分配空间。它不是简单把窗口按比例切成几个盒子。一个按钮即使 stretch 为 1，也可能由于样式或尺寸策略不愿竖向拉高；多行编辑器通常适合承担更多可伸缩空间。

按执行顺序拆解

打开 mainwindow.ui，在 centralwidget 下找到 verticalLayout，内部依次是 formLayout、gridLayout 和 buttonLayout。表单项设置 row/column，网格放置六个按钮，底部水平布局包含伸缩占位和确定/取消按钮。外层边距为 20、spacing 为 14。C++ 不重复创建布局。

参数与行为边界

contentsMargins 是容器内缘留白，spacing 是相邻项目间隔，addSpacing 是固定间隔，addStretch 是可伸缩空白。QGridLayout 的 rowSpan 和 columnSpan 允许跨行列。QFormLayout 不等于 QTableWidget：前者安排控件，后者显示可编辑表格数据。

易错点与排查

布局不是可见控件。控件加入布局后不要再依赖 move()/resize() 固定摆放。不要给同一 QWidget 安装两个顶层布局；QMainWindow 先设置 centralWidget，再给这个容器安装布局。

遇到问题时先区分三个层次：编译错误检查声明、头文件与构建配置；界面无反应检查连接、接收对象与生存期；运行结果不对检查输入、返回值和分支是否真正执行。可以先在连接入口记录一条日志，再在结果处理处记录一条，定位中间哪一步没有到达。

9.4 堆叠页面与窗口切换

对应示例：完整源码。先运行项目观察行为，再按以下顺序阅读。

9.4.1 本章要解决的问题

QStackedWidget 在同一容器里管理多个页面，一次显示其中一页。addWidget 返回该页索引；setCurrentIndex(0) 切到第一页，索引从 0 开始，也可用 setCurrentWidget 按指针切换。切换不会删除其他页面，输入状态通常仍保留。

这与 hide 一个顶层窗口、show 另一个顶层窗口不同。用堆叠控件实现“登录页面—主页”能够共享同一个顶层窗口，方便统一管理退出和生命期。多窗口方案也可用，但要管理返回路径、对象所有权，以及隐藏主窗口后子窗口关闭导致程序无可见窗口的情况。

9.4.2 页面属于一个窗口 生命周期仍然存在

QStackedWidget 在视觉上一次显示一页，但其他页面的对象通常仍存在，因此输入状态也可保留。这适合向导、设置页和简单导航。切换页面不会自动执行登录验证，也不会自动清除敏感信息或刷新数据；这些都需要明确的进入与退出逻辑。

9.4.3 按执行顺序拆解

本章要解决的问题

QLineEdit 用于单行输入，setText 写入，text() 读取真实内容。placeholderText 是空内容时的提示，不是输入值；设置它不会让 text() 返回提示。textChanged 会响应用户和代码设置的变化，textEdited 主要响应用户编辑，returnPressed 用于回车触发。

四种 EchoMode 为 Normal、NoEcho、Password、PasswordEchoOnEdit。NoEcho 不显示字符；Password 显示掩码；PasswordEchoOnEdit 在编辑时显示、非编辑时掩码。显示模式只改变外观，text() 仍是实际字符串。setTextMargins 控制框内边距，不是移动控件本身。

输入值 显示值和编辑动作

把内部结构藏在稳定接口后面

对应示例：完整源码。先运行项目观察行为，再按以下顺序阅读。

本章要解决的问题

QStackedWidget 在同一容器里管理多个页面，一次显示其中一页。addWidget 返回该页索引；setCurrentIndex(0) 切到第一页，索引从 0 开始，也可用 setCurrentWidget 按指针切换。切换不会删除其他页面，输入状态通常仍保留。

这与 hide 一个顶层窗口、show 另一个顶层窗口不同。用堆叠控件实现“登录页面—主页”能够共享同一个顶层窗口，方便统一管理退出和生命期。多窗口方案也可用，但要管理返回路径、对象所有权，以及隐藏主窗口后子窗口关闭导致程序无可见窗口的情况。

页面属于一个窗口 生命周期仍然存在

QStackedWidget 在视觉上一次显示一页，但其他页面的对象通常仍存在，因此输入状态也可保留。这适合向导、设置页和简单导航。切换页面不会自动执行登录验证，也不会自动清除敏感信息或刷新数据；这些都需要明确的进入与退出逻辑。

按执行顺序拆解

参数与行为边界

currentIndex 从零开始，空容器可能没有有效当前页。setCurrentWidget 比硬编码数字更能表达意图，但仍要求页面已经加入。removeWidget 不等于 delete：移除后对象是否继续使用、重新设 parent 还是释放，需要自己决定。

10.1 事件循环与对象通知

QApplication::exec() 进入事件循环后，程序持续处理鼠标、键盘、尺寸变化和重绘等事件。QEvent 对象描述某次事件，事件系统把它交给目标 QObject；QWidget 的 event 会按类型分派到相应的处理函数。

信号槽用于对象之间通知和调用处理逻辑，事件机制处理输入和窗口等事件。一个用户动作可能先由控件处理事件，再由控件发出信号，但两者不是同一个接口。下面从具体事件进入，不需要自己建立轮询按钮的 while 循环。

10.2 关闭事件与尺寸变化

对应示例：完整源码。先运行项目观察行为，再按以下顺序阅读。

10.2.1 本章要解决的问题

事件是 QEvent 的对象，由事件系统送到目标 QObject。QWidget 的 event() 会根据类型分派到 closeEvent、resizeEvent 等专用处理函数；按钮 clicked 则是较高层的信号通知。二者经常配合，但不是同一个概念。

在头文件 protected 区声明 void closeEvent(QCloseEvent *event) override，源文件实现。accept 允许关闭，ignore 拒绝关闭；不要调用 close() 重新触发自己。resizeEvent 的 size 是新尺寸，oldSize 是旧尺寸，首次事件的旧尺寸可能无效。resizeEvent 中尽量避免无条件再次 resize，以免递归。

10.2.2 关闭请求和尺寸通知是不同事件

closeEvent 收到的是关闭请求，ignore 可以让窗口继续存在；resizeEvent 通知的是尺寸已经变化，不是拿来询问是否允许缩放。不要在 closeEvent 里再次调用 close 引发递归，也不要在 resizeEvent 中无条件再次 resize 制造事件循环。

10.2.3 按执行顺序拆解

mainwindow.ui 的中央标签提升为 EventArea，eventarea.cpp 的 resizeEvent 显示区域尺寸。mainwindow.h 声明主窗口 closeEvent，mainwindow.cpp 根据 Yes/No 决定 accept/ignore。关闭逻辑在主窗口，尺寸显示逻辑在中央区域，职责分开。

10.2.4 参数与行为边界

事件参数只在当前调用中有效，不要把 QCloseEvent* 或 QResizeEvent* 保存到异步回调后再使用。若要异步询问关闭，可以先 ignore，本次事件结束后显示异步对话框，确认后设置状态并重新发起关闭请求。

override 用于检查是否真正覆盖了基类虚函数。保留原有处理通常要调用基类对应函数，但关闭拦截中拒绝后不要再调用会重新接受关闭的默认处理。本例自动验证会分别选择 No 与 Yes。

10.4 重写 event 拦截 Tab

10.4.1 本章要解决的问题

event(QEvent *) 返回 bool，表示是否处理这个事件。先检查 type 再把通用指针转换到对应事件类型；未经类型判断的强制转换可能访问错误的数据。处理感兴趣的事件后返回 true；其余事件必须 return 基类::event(event)，避免破坏默认行为。

10.4.2 事件分发 事件处理和事件过滤

特定处理函数适合某一类事件；重写 event 适合介入目标对象的分发；eventFilter 适合在不改被观察对象继承关系时提前观察或消费事件。示例 51在 QLineEdit 上安装过滤器，识别回车并更新标签，不需要创建 QLineEdit 子类。

10.4.4 参数与行为边界

本章要解决的问题

事件是 QEvent 的对象，由事件系统送到目标 QObject。QWidget 的 event() 会根据类型分派到 closeEvent、resizeEvent 等专用处理函数；按钮 clicked 则是较高层的信号通知。二者经常配合，但不是同一个概念。

11.1 QPainter 与绘图设备

对应示例：完整源码。先运行项目观察行为，再按以下顺序阅读。

11.1.1 本章要解决的问题

QPainter 执行画线、矩形、椭圆、图片和文本等操作；QPaintDevice 是可被绘制的设备基类；QPaintEngine 提供设备对应的绘制实现，入门通常不用直接操作。原笔记中的 QPainterDevice 应改为 QPaintDevice。

对 QWidget 绘制应在 paintEvent 或其调用链中完成。先创建 QPainter(this)，设置 QPen 控制边线颜色宽度，设置 QBrush 控制填充，再调用 drawLine、drawRect、drawEllipse。要改变图形，更新成员状态后调用 update() 请求重新绘制，而不是把绘图只放进按钮槽临时画一次。

QPixmap 常用于界面显示，QImage 便于像素访问，QBitmap 是一位深度位图，QPicture 记录与重放绘图命令。它们不是全部绘图设备，QWidget 也是 QPaintDevice 的子类。

11.1.2 图形应该从持久状态重建

绘制结果是窗口某一时刻的像素，不是可靠的应用状态。遮挡、缩放、主题变化等都可能触发重绘。把“画一个红椭圆”只写在按钮槽里而不保留颜色状态，下一次重绘可能消失。示例 52将 color_ 放在 DrawingArea 成员中，按钮只更新颜色并 update，paintEvent 每次根据状态重建图形。

11.1.3 按执行顺序拆解

mainwindow.ui 中 QWidget 已提升为 Canvas；mainwindow.cpp 只负责装载界面和状态提示。绘制逻辑独立在 canvas.cpp 的 paintEvent：创建局部 QPainter、设置画笔和画刷、绘制形状与文字，再绘制离屏 QImage。示例 52继续让绘制由成员状态驱动。

11.1.4 参数与行为边界

QWidget 是屏幕控件，QImage 便于像素操作，QPixmap 为界面显示优化，QBitmap 是一位位图，QPicture 记录绘制命令。逻辑坐标、像素坐标与设备像素比需要区分。painter.save/restore 可隔离画笔与坐标变换状态，复杂绘制中比反复手动恢复属性更可靠。

11.1.5 易错点与排查

QPicture 不是普通像素图片。QImage、QPixmap 上的离屏绘制可以在适当代码位置进行，不要求它们自己的 paintEvent。一个设备同时只应有一个活动画家；使用局部 QPainter 作用域可自动结束绘制。

遇到问题时先区分三个层次：编译错误检查声明、头文件与构建配置；界面无反应检查连接、接收对象与生存期；运行结果不对检查输入、返回值和分支是否真正执行。可以先在连接入口记录一条日志，再在结果处理处记录一条，定位中间哪一步没有到达。

void Canvas::paintEvent(QPaintEvent *)
{
    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing);
    painter.fillRect(rect(), Qt::white);
    painter.setPen(QPen(Qt::darkGray, 2));
    painter.drawLine(35, 35, 500, 270);
    painter.setPen(QPen(Qt::red, 3));
    painter.drawRect(60, 70, 360, 180);
    painter.setPen(QPen(Qt::blue, 5));
    painter.drawEllipse(60, 70, 360, 180);
    painter.setPen(Qt::black);
    painter.drawText(50, 320, "QPainter 在 paintEvent 中绘制，缩放和遮挡后仍可重绘。");
    QImage image(180, 80, QImage::Format_ARGB32);
    image.fill(QColor("#dbeafe"));
    {
        QPainter imagePainter(&image);
        imagePainter.setPen(Qt::darkBlue);
        imagePainter.drawText(image.rect(), Qt::AlignCenter, "QImage 离屏绘图");
    }
    painter.drawImage(50, 360, image);
}

构造与析构为什么这样写

Widget::Widget(QWidget *parent)
    : QWidget(parent)
    , ui(new Ui::Widget)
{
    ui->setupUi(this);
}

Widget::~Widget()
{
    delete ui;
}

初始化列表先构造 QWidget 基类，再创建生成的 Ui::Widget 辅助对象。Ui::Widget 本身不是窗口：它保存 Designer 中各控件的指针，并提供 setupUi。调用 setupUi(this) 后才会建立控件、属性和布局，因此访问 ui->pushButton 等成员必须写在它之后。

ui 指向的辅助对象由窗口类负责 delete。按钮、输入框等 QWidget 实例主要通过 QObject 父子关系管理，不需要把每一个 ui->控件指针再手动 delete 一遍。不要删完 ui 后继续在析构函数中用 ui 访问控件。

.ui 放外观，.cpp 放行为

固定按钮、标签、输入框、页面、菜单、QAction 和布局放入 .ui。Lambda 的定义和调用、运行时状态、文件读写、事件处理与 QPainter 绘制留在 .cpp。

Qt 标准文件、颜色和字体对话框由 Qt 提供，不需要复制它们内部的 .ui。示例 36 和 50的自定义对话框使用 dialog.ui。QStatusBar 的普通/永久状态控件需要调用 addWidget / addPermanentWidget，演示代码保留了这部分动态添加操作。

示例 01—30使用 geometry 放置演示控件，便于观察坐标和 Lambda 输出；示例 40集中学习布局，后续项目采用可随窗口变化的布局。没有为早期固定坐标练习偷偷添加布局，因为布局会覆盖手工位置。

两种连接方式分别在哪里

大多数示例显式调用 connect，便于追踪信号、接收对象和 Lambda。访问成员 ui 时使用 [this]；它捕获当前窗口指针，不会复制整个界面。

示例 35单独示范 Designer 常见的自动连接：objectName 为 runButton 的按钮，对应声明在 private slots 下的 on_runButton_clicked()。setupUi 最后调用 connectSlotsByName。不要再为同一个槽重复写 connect，否则会执行两次。改变 objectName 后也必须同步改槽名。

第 36、50 步 dialog.ui 的“信号/槽编辑器”连接 buttonBox 的 accepted() → Dialog::accept()、rejected() → Dialog::reject()，可以直接在 Designer 中查看。

自定义控件如何在 Designer 中显示

示例 43在 mainwindow.ui 中放置两个 QWidget 占位，分别提升为 SmallWidget，提升头文件为 smallwidget.h。SmallWidget 内部的 QSpinBox、QSlider 则在 smallwidget.ui 中设计。两个实例各自拥有自己的 Ui 和数值。

示例 45—47将 QLabel 提升为 EventArea，头文件 eventarea.h。示例 48将 QWidget 提升为 Canvas，头文件 canvas.h；示例 52将 QWidget 提升为 DrawingArea，头文件 drawingarea.h。提升信息已经保存在对应 .ui 的 customwidgets 中。

从空模板重做时，在占位控件上右键选择“提升为”，输入准确的类名和头文件名，添加后点击提升。自定义类必须提供接受 QWidget *parent 的构造函数，并在 .pro 的 SOURCES/HEADERS 中加入实现。Designer 中显示占位区域是正常的，自己的 paintEvent 会在运行后绘制。

编译时发生什么

qmake 从 FORMS 读取 .ui，再让 uic 生成 ui_*.h；从带 Q_OBJECT 的头文件生成 moc 代码。CMake 入口同时开启 AUTOUIC、AUTOMOC 和 AUTORCC。两种入口使用相同的源文件和表单。

如果提示 ui_xxx.h 找不到，检查 .pro 的 FORMS 和 #include 名称，重新运行 qmake 再构建。如果提示某个 ui->成员不存在，检查 Designer 的 objectName，保存 .ui 后重新构建。不要通过手改生成文件暂时消除错误。
